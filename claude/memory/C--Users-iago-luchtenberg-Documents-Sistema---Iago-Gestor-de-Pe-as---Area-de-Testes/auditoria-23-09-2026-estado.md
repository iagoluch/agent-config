- ~~Freio de login usa IP do túnel~~ — INVESTIGADO 23/09/2026 e REJEITADO: a chave já é `ip:username` (`backend/api/routers/auth.py:39`, `_login_throttle_key`). Atrás do túnel Cloudflare, `request.client.host` é sempre o mesmo peer local (cloudflared → uvicorn), então o componente IP já é constante para todo o tráfego — a chave já degrada, na prática, para "só por usuário", que é exatamente o comportamento que a "correção" proporia. Trocar a chave para usar só `username` seria um no-op: mesmo particionamento, zero mudança de comportamento. Nenhum código de X-Forwarded-For/CF-Connecting-IP existe no projeto para extrair IP real do cliente por trás do túnel, então não há informação melhor disponível para usar. Não aplicar (nada a corrigir).
